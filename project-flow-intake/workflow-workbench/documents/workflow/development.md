# 开发约束与启动 · 通用流程定义

范围：通用流程草案，尚未安装为Codex Skill。修改后不自动影响已有项目的采用版本。

跨阶段指令按[复合任务拆解与阶段交接](project-start.md#复合任务拆解与阶段交接)执行；本页维护开发专业标准。先判断任务依赖，只有实际启用多个AI执行者时才进入下述并发分支；局部完成与最终集成分别验收。

## 节点

### 1. 接收业务基线

用户输入：提供已确认业务交接包，说明本次是准备开发、接续或版本迭代。

分析：核对正文版本、确认范围与后续决定，将需求/阶段/当前状态/证据/未决事项对应；区分业务确认版与开发目标。；当前摘要与历史记录冲突时定位有效决定，不只按页首、最大编号或追加顺序判断；已完成范围不重新立项。

产物：开发接收清单：当前范围/版本、完成与待办状态、决定/证据定位及缺口。

确认：仅对缺失或互相冲突的关键决定补充确认。

进入条件：本期范围与状态有依据，关键冲突已澄清；不将旧待办或未来建议自动当新任务。

### 2. 识别项目与现状

用户输入：补充实际仓库/运行环境和部署限制；无工程时说明新建需求。

分析：按本期启用端、角色、运行形态、集成与数据要求判断；对照真实源码、锁文件、入口说明和进度，保留现有可用架构。；核对工作区及未提交成果；命令区分只读检查、准备写入、启动与验证，标前置、环境/端口、数据目标和副作用。盘点不自动执行setup、seed或重启。

产物：项目与工程画像、复用/选型清单；必要命令及其环境、前置与写入影响。

确认：确认重要选型或迁移取舍；已确认且仍适用的技术决定不反复确认。

进入条件：工程与依赖事实、工作区成果及首批范围清楚；必要命令有适用场景，不为套模板重建或重置。

### 3. 制定约束与红线

若接入时识别到参考交互复现或核心动效需求，转入[设计与组件库的可选分支](design.md#可选分支参考交互与动效)。按首个代表交互的验证结果决定实现方式及依赖，在本项目的实现约定中登记采用依据。

用户输入：提供既有技术/安全/设计规则及组织限制。

分析：按业务和现有工程补必要约束，区分既有规则、工程事实与新增建议；说明依据、影响、适用端/版本、检查及替代关系。；契约正文单点维护，快照引用基线与实际差异；沿用项目有效记录要求，不未经确认删除历史或减少必需记录。业务规则留PRD，Token独立接入。

产物：技术约定与红线的补差/冲突清单；权威入口和记录职责，避免另建同义文件。

确认：确认会影响首批开发的重要规则与取舍；一般实现细节在已有授权内处理。

进入条件：当前批次相关冲突已处理，规则可执行可检查；不要求远期所有未知都解决。

### 4. 核对开发条件

用户输入：明确本期开发采用版本、任务目标与授权范围。

分析：将具体首批任务关联PRD验收、开发目标、工作区/源码基线、范围/不做项、依赖和结束条件；不因流程齐备自动启动新功能。；按实际变化及影响选择验证，历史证据注明对应版本/环境/层级及未覆盖项；不作为当前全量通过。核对当前任务所需账号/接口、环境及迁移回退条件。

产物：绑定具体任务与基线的开发单；适当验证计划、进入条件和相关阻塞清单。

确认：复用已有明确开发授权；未明确时补目标版本/范围。业务新版确认不会自动切开发。

进入条件：具体任务、目标版本、授权与当前批次依赖清楚；历史通过不能代替本次检查，阻塞只暂停相关部分。

### 按需分支：多AI窗口并行开发

适用：同一用户使用多个AI窗口或Agent，在同一项目内并行开发不同页面或功能。单窗口任务不启用。本分支由一个AI窗口统筹任务和集成，执行窗口按边界实施；不要求多个人工参与，也不要求用户逐步确认。产品取舍、重大范围变化和必须人工验证的事项按现有授权规则处理。

先判断任务能否独立：不同页面仍可能共享导航、Token、公共组件、路由、依赖或数据。共享契约未稳定时先完成必要公共基础；高度耦合或拆分收益不足时顺序执行，不为并发而拆分。并行前核对仓库、未提交成果和基线，不自动提交、重置或搬移用户修改。

**隔离准备的结束条件**：有效基线可定位、独立工作区已就绪、修改范围及必要共享依赖已明确、可直接执行的交接指令已提供，四项满足后即交付“准备完成”。交接指令包含任务标识、真实工作区路径、基线、应读规范、允许范围、必要前置、适用验证和结果回写位置；明确当前未执行的检查。准备完成不等于页面开发或最终集成通过。

先把交接指令交给用户或已获授权的执行窗口，再继续统筹窗口其他工作；同一长指令包含首页开发时，首页仍作为后续任务推进，不吞掉准备阶段的交付。记录补写限于接手必需信息；过期但不影响当前范围的说明、无关资料归档、格式统一及非阻塞清理留作后续，不作为启动门槛。只处理会影响接手的基线缺失、实际依赖故障或隔离冲突，不为准备任务扩展到全项目治理。

本轮已读取的规则、配置与验证证据，在来源和相关基线未变化时复用摘要及定位，不重复全文加载。准备阶段只核对接手所需条件；依赖安装、完整构建或浏览器走查仅在它们影响本次启动，或项目已有明确要求时执行，其余明确交给执行窗口或集成阶段。不能仅为工作区全绿反复运行未变化检查；代码、依赖、配置、运行环境变化，出现新失败或既有证据不适用时，定向重读和复测受影响部分。其他窗口可能更新的任务状态和共享契约，在实际接手、写入或合并前重新核对，不能用缓存替代并发状态检查。

在现有项目开发单及交接记录登记，不另建任务体系：

| 字段 | 执行要求 |
| --- | --- |
| 任务与窗口 | 稳定任务ID、负责页面/功能、执行窗口标识及集成窗口；交接后更新负责方 |
| 采用基线 | PRD、设计规范和组件契约的采用版本，以及代码基线提交；共享变更后登记新基线 |
| 工作区与边界 | 分支、独立worktree绝对路径、允许修改范围；页面以外的必要改动先协调归属 |
| 依赖与共享变更 | 上游任务、共享文件/接口及本批唯一执行方；按实际依赖决定顺序，不永久固定某个窗口拥有所有公共文件 |
| 验证与状态 | 结束条件、实际验证、提交或可复核差异、阻塞与下一步；区分页面完成、待集成和集成通过 |

默认每个并行写入任务使用独立分支与worktree；仅开不同窗口或不同分支但共用工作目录不构成隔离。不能使用worktree时记录实际隔离方式；同一文件的写入串行处理，必要时整个任务改为顺序执行。worktree不隔离数据库、服务、凭据或外部数据：仅在实际使用时分配端口和测试数据，避免修改对方服务或共享正式数据。

需要变更共享文件时，在现有任务记录协调归属及受影响任务，由指定窗口实施并验证，再交接可用提交/差异。执行窗口在可用基线接入后继续；不能因本地没有文本冲突就认定接口或行为兼容。没有跨窗口消息工具时，用明确的交接记录衔接，不声称已自动通知或派发。

各执行窗口先完成本任务验证，提交交接：基线、实际修改、验证结果、未决项及依赖。集成窗口核对工作区后按依赖合并；普通冲突在已有授权内处理，语义冲突或产品取舍不能猜测。合并后验证构建及适用的跨页面导航、共享样式/组件与业务路径。只回退本任务明确归属的变更，不丢弃其他窗口或用户成果。

验收：任务修改范围可定位，共享修改无重复执行方；各页证据与最终集成基线对应；失败或未知项保留，未合并不标整体完成。首次采用可用隔离最小项目验证独立页面开发、一次共享变更交接和集成检查；只有实际发生或隔离模拟过的冲突处理才记通过。规则记录不等于自动调度、文件锁或真实并发试跑已实现。

### 5. 按批启动与回写

用户输入：按需处理实施中出现的新取舍或目标变化。

分析：未来执行前核对工作区基线；保留用户成果，完成该批实现及相称验证，记录已验证/未验证与剩余问题。；记录使用稳定任务/记录ID、来源位置和基线指纹；旧编号保留，冲突先定位。实际文件变动与差异单独登记，计划不记成已完成。

产物：该批实现与对应证据；稳定记录定位、实际变更/待同步清单及当前状态。

确认：重大范围、版本或规则变化定向确认；普通可逆实现按已有授权推进。

进入条件：任务结束条件有证据，已验证/未验证与剩余问题明确；本页只展示方案，不启动任何工程。

## 产物规则

- 开发接收与工程画像：当前范围/版本、工程事实、完成/待办状态、来源与证据、缺口；补入现有权威入口，历史状态不冒充当前。 
- 技术实现约定与红线：按实际栈和当前范围补齐，标依据/适用端/版本/验证；沿用有效规则，冲突明确替代。 
- 首批开发任务与验收：具体任务关联PRD和当前基线，明确范围/不做项、依赖、相称验证及结束条件。 
- 实际执行与文件记录：执行后以稳定ID及来源定位记录实际路径、差异、证据层级和未同步项；遵守项目现行记录要求，不另抄契约。
