# 设计规范文档与规范库封装

从[设计流程](design.md)按需进入。普通设计稿只整理本批真实参数；Token生成、组件归库和发布按任务授权分别启用。历史见[历史记录](design-history.md)，项目特例仅在匹配项目时读取[项目采用记录](design-project-adoptions.md)。

当用户要求提取参考风格、整理可维护设计规范或发布可复用 Figma 库时启用；普通页面任务不强制建库。需要新建Token时再读[无Token设计稿归纳](design.md#按需分支无-token-设计稿归纳)；普通参数文档沿本页命名查重和呈现规则，不加载无关映射步骤。先识别以下模式：

| 模式 | 输入与产出 | 进入下一步 |
| --- | --- | --- |
| 草稿 | 从本批设计稿提取已观察值，在设计稿旁整理用途、候选变量、样式、组件及缺口；已有有效资产优先复用 | 用户确认采用的范围后，可进入封装；草稿不自动成为正式规范 |
| 规范库封装 | 已确认的设计资产与明确的目标 Figma 文件；整理真实变量、样式、组件、文档模板及可跳转目录 | 完成绑定与代表页面验证后形成发布候选；实际发布按授权与账户能力执行 |

#### 目标与模板配置

在现有基线/映射记录维护：设计源文件及节点、目标库文件、采用版本和端、产品 Token/样式/组件身份、命名词表、文档主题、文档模板来源及主组件 ID/key、内容类型到模板的对应关系、开放属性和允许调整范围。值未知时明确待补，不猜测组件身份。空目标链接只表示目标位置，不提供视觉基线；从已确认设计源和模板读取。

产品视觉与规范文档视觉独立维护。产品 Token 控制示例组件的风格；文档主题控制页头、说明、表格和目录的风格，不随更换文档主题改动产品示例。不得把某个文件的 Ant 分类、固定页头高度、8px网格或具体字体变成跨项目默认值。

用户可以用自然语言修改模板的允许项、禁止项及适用范围。将明确要求写入上述配置，说明替代关系；只作用于本次的要求不自动升级通用规则。配置与实际 Figma 资产不一致时，先指出差异再按已授权范围修正。

#### 规范文档生成约定（内部执行入口）

适用对象为设计规范及 Token 规范库的目录、说明、参数表与样张等文档呈现，不是产品页面的视觉规范。执行顺序：确定范围 → 读取当前模板与项目资产 → 匹配模板 → 生成或增量更新 → 分层验收 → 同步采用记录并交付。普通文档更新不自动启动 Token 提取、产品组件建库或发布。

## 设计规范呈现契约（2026-11-08）

用户明确指定为后续设计规范的默认产出方式；取代本分支把参数规范与 Token/语义化展示默认合并的做法。项目后续明确覆盖仍优先，产品值不得从文档模板继承。

- **范围与数值**：只提取本批指定设计稿实际出现的规范参数；保留实际字体、字重、字号、行高、字距、间距、圆角、颜色及不透明度等组合。不得为了凑整或形成常用阶梯补值、改值、抹除真实组合差异。同字号或同基础色可归并展示，但仍保留其实际参数组合与用途。明确要求的类别、阶梯或对照位置缺值时保留空白占位；不得用模板示例值填充，也不自拟缺失档位或未经确认的色阶编号。
- **规范与 Token 分离**：设计规范默认不生成或展示 Token、变量命名、别名、语义角色与代码映射；这些内容仅在用户另行明确要求时进入相应分支。已有变量可作为读值依据，不因生成文档修改变量表。
- **标题与文案**：规范标题使用单一、直接的类别名，如「色彩」「文字」「边距」「间距」「圆角」，不把不同规范合并成「文字、表面与操作」等标题。规范页头使用已采用的 `Docs / Page Header`，填写标题和简短描述并显示描述。页头描述只说明本页规范范围；正文采用「标题＋描述＋内容」或「标题＋内容」，描述按需要保留，不强行为每个模块凑文案。
- **正文内容**：普通规范优先用图形样张、数值及简短描述展示；需要 Token 命名时才单独使用表格。用户明确要求保持原表达的模块（如当前渐变）沿用原结构，不能为统一样式擅自重绘。使用场景简写为「标题」「Hero」「工牌」等；已有表格采用「描述」列，图形卡使用对应描述文字。禁止向阅读正文注入「此数值来源于…」、工具操作限制、生成过程、内部布局参数、来源追溯或实现状态等无关说明。来源、模板采用与验证证据写入维护记录和组件说明，不混入规范阅读正文。
- **色彩归类**：按「主题色、功能色、中性色、带有品牌倾向的中性色、扩展色」组织。文字使用的灰、黑、白及带倾向的近中性色归入相应中性色类别，不单设「文字颜色」或复制同一色值；文字用途仅作描述。只归类并保留实际颜色，后续删除或调值由用户决定，不因去掉独立文字分类而删色。只展示已观察颜色，依明暗排序；有明确原始阶梯身份时才沿用编号。主题/功能用途不明确时不擅自认定。缺失颜色或档位以空白占位表达，不自动插值或套用 TDesign 示例色板。
- **不透明度与渐变**：项目显式调整见[项目采用记录](design-project-adoptions.md)；仅对相应项目和范围生效。统一放在色彩规范。同一基础色只有一个阶梯，字体、背景、图形与描边共用其已观察不透明度的并集；仅基础色不同（如 `#FFFFFF`、`#000000` 或其他实际颜色）才分开。每档以实心色块呈现，标实际色值、不透明度，必要时简写 font/bg/stroke 使用范围；不因用途不同重复生成同色阶梯。实色灰不能推算为未出现的透明度。渐变属于色彩规范，已有模块可原样迁入，避免保留一份独立渐变规范重复维护。
- **文字阶梯**：以实际字号分档排序，样张必须使用该档真实字号，不能所有样张用同一文档字号后只改数字标签。同字号内汇总实际字重（如粗体/中等）和行高，用 `/` 并列实际存在的行高，包括与字号相等的行高；Auto 保留 Auto，不补数值。同档保留不同字体、字重、行高、字距的真实对应组合，不能把汇总值任意交叉组合。每档说明实际用于哪些位置。字体不可加载时保留源字体名称与参数，说明尺寸示意所用文档字体；不改产品稿字体，不声称已还原字形。
- **间距（包含边距）**：边距、内距、外距与元素间隔统一在一份「间距」规范中，按实际使用层级分为元素间距、卡片间距、内容间距、模块间距、页面间距等；只保留设计稿有依据的类别。分类依据实际容器与使用关系，不以数值大小猜测。同一数值可出现在不同类别，各类别内部去重、升序；不生成语义化 Token、用途命名映射或上/右/下/左应用组合，不另保留边距规范。每档用独立实心矩形表示，宽度等于实际数值，统一示意高度，下方标数值与单位，横向排列并按需换行；不用夹元素组合或重复边框卡片。示意高度、排版距离及用户案例数字不是产品参数，不补未观察阶梯。本条替代此前「单一无分类阶梯」及分开维护边距的旧约定。
- **描边**：只记录实际朝向/边、粗细和对齐（内描边、居中、外描边）等几何属性；按这些属性组合查重。颜色、不透明度、纯色/渐变变化不生成新的描边档位，这些参数在色彩规范维护。图形样张可用统一文档示意色增强可读性，但不得改产品描边；未出现的方向、粗细或对齐方式不补。
- **背景模糊**：同时交付直观图形样张和参数表，不能只画效果卡。表格至少列出实际模糊类型和半径（含单位），源资产有其他已观察模式或相关参数时再列入；不拿样张演示用的背景、透明度等数值冒充产品模糊参数，不补默认值。此为用户明确指定的表格例外，不受普通规范仅在 Token 命名时使用表格的默认限制。
- **标注层级**：所有规范移除展示序号与页码序号，保留实际参数和已有资产命名身份。关键数值、描边朝向与内/居中/外对齐等重要标注提高字号与可读性，辅助用途说明保持次级层级；文字样张仍使用真实字号，不因文档强调而改变参数样张。
- **正文精简与留白**：文字字号模块取消装饰性描边；圆角展示卡与样张取消描边，图形适度缩小但保留真实圆角值。圆角按设计稿实际使用范围分为元素圆角、卡片圆角等，各类别内去重、升序，同值确有跨类使用时可分别保留。只展示类别标题、样张和数值单位，删除逐项「圆角／工牌」等语义或用途描述，不按数值阈值猜测分类。文档样张尺寸和分类留白按已采用模板或项目展示约定读取；项目特例见[项目采用记录](design-project-adoptions.md)，不作为产品参数。正文不再重复页头主题或「主题＋阶梯」总标题，保留元素间距、卡片间距、色彩分类等有区分作用的子标题；通过实例标题组显隐处理，不修改默认源组件。
- **排版采用**：页头以默认源 `3:25` 的实际组件、开放属性和显隐规则为准。正文优先实例化下表登记的模块组件；标题组、描述、内容之间的间距及字体、尺寸模式从当前源资产读取。正文父级只负责模块之间的间隔；模块内部负责标题组到内容的间隔，不能再由父级叠加同一留白。一个模块包含连续多张参数表时，它们属于同一内容槽位，不给每张表重复增加无意义标题。
- **组件调用**：只覆盖公开文字、描述显隐和 `Content` 槽位。内容槽位接收本批已有参数表、色阶样张或视觉样张；不能复制模板中的 Blue 色值等示例数据进入项目规范。新模块不可跨文件导入时按下文快照规则处理，登记源/目标身份及同步责任，不冒充远程实例或自动发布。

验收同时检查：页头有简短描述；模块符合两种结构之一；间距符合已采用源；保留实际参数及空白位置；没有 Token/语义化与过程说明混入；长标题、描述显隐和表格增高不会裁切。用户只要求当前设计稿规范时，不额外生成无关页面、组件规范或说明章节。

#### 生成与增量更新

1. 读取当前项目已确认的规范、变量、样式和组件，按真实内容组织章节、分类、条目与目标；模板占位和参考分类不代表已有资产。未要求的无内容分类不新建空页；用户要求保留的规范类别和阶梯对照位置按呈现契约留空占位。
2. 按下节内容类型匹配真实模板，使用实例和公开属性。具体内距、列轨道、字体及尺寸模式从采用资产读取；父级Gap与内容内距不重复提供同一留白。差异超出公开范围时按既有候选流程处理，不擅改源头。
3. 新生成先用本批代表内容试跑；更新先定位既有实例和手工修改，对照上次基线处理差异。保留组件、变量和实例身份，不按同名覆盖，不因改文案重建资产。
4. 目录条目分别绑定真实目标，改名、增删及重排后重绑受影响的链接范围。默认实例不保留占位链接；规范值从实际变量和模式读取，同步检查展示文字。
5. 按「分层验收与测试调用」完成适用检查，并同步实际组件、语义说明与项目采用记录。源头说明发现缺陷但无修改授权时登记差异及影响，不声称三者已一致；在已授权目标内继续可独立完成的工作。

命名沿用项目职责和现有词表，写入前按用途、作用域、类型与身份查重。规范文件采用「主题名称＋规范」；组织/工具页保留职责名，不给所有层级强加后缀。Token名称表达视觉角色，文档图层名称表达结构职责，不预设业务词表、不为统一名称重建稳定资产。文件名与画板名分别核对。

源头修改沿通用红线R01；本分支的生成、更新或一致性检查不自动授权修改源组件、变量、样式或规范。产品视觉与文档主题仍按「目标与模板配置」分别维护。

#### 模板实例选择

先读取目标库及指定模板源中的真实组件、属性和既有实例。截图名称只作定位线索，不能凭名称认定已建立模板调用。按内容用途选择现有模板，使用实例及开放属性；模板不存在或不适用时，在设计稿旁试做候选，用真实内容验证后再按确认范围归库。新增文档排版属于文档模板，不能混入产品组件分类。

| 内容类型 | 选用依据 | 验收重点 |
| --- | --- | --- |
| 规范页头 | 已确认页头模板及标题、简短描述等开放属性 | 主组件身份、标题层级、描述显示、内容增长与允许高度 |
| 正文模块 | 标题＋描述＋内容，或标题＋内容模块；参数表与样张放入内容槽位 | 源组件身份、描述显隐、内部与外部留白职责、长文增长，不混入模板示例数据 |
| 变量与参数 | 已确认参数表或色阶模板 | 真实变量值、别名/模式、用途及示例绑定 |
| 状态与用法 | 已确认状态矩阵、示例或对照模板 | 实际状态覆盖、长文重排、示例组件身份 |
| 目录 | 本批真实分类与目标节点 | 每项分别绑定正确目标，无整段共用错误链接 |

模板登记包含必填/可选区域、长文及多行增长、示例比例和缺内容时的处理。缺信息标待补，不能为填满模板编造规范。模板允许的范围内自动适配；超出时提出模板变体或新模板候选，不任意重排已采用模板。

现有文档排版按用途登记语义模式，先复用对应结构和元素，不为每张表、每个数据行或每种内容创建主组件。仅当元素或组合出现稳定的实际复用需求时再组件化。列职责不同不视为重复：当前默认源中三列说明、四列双主题色阶、五列带描述的语义颜色、四列单值说明分别沿用其示例；重复的表头、外框和分隔线统一到已确认基础表格。具体列宽与参数从实际项目及选用样例读取，不固定为通用值。Footer 身份与使用说明一并登记，远程实例不冒充本地主组件。

表格仅在可见数据行之间绘制横向分隔线，最后一条可见数据行不额外绘制底线；外框由表格父容器承担。新增、删除或显隐数据行后重新判定末行，不按图层树中的隐藏末行判断。未提供自动末行逻辑的组件，由生成/更新流程明确处理实例边线并核对，不宣称仅改变显隐属性即可自动更新。

#### 查重、归库与维护

按用途、结构、属性、状态、主题含义及已有身份查重，而不只比名称或数值。已有能力直接复用实例；已有组件的新状态优先扩展原变体；真正新能力先在设计稿验证；仅属项目业务的组合保留项目范围。已明确批准的资产可直接按授权归库，不重复要求确认。

仅在规范库封装范围内，按真实资产生成首页/目录、基础规范、组件、适用业务组合、文档模板及维护说明；未要求的无内容分类不建空页，明确的缺值对照位置留空占位。仅在已授权的 Token/语义化范围内组织基础值、语义角色和必要组件变量，组合效果与字体可使用样式。普通设计规范文档沿前述参数呈现契约。保留已有变量/组件身份，不因归类或改名重建同义资产；迁移跨文件时登记新旧身份及引用替换，核对原稿实例和变量依赖，不承诺复制后自动保留跨文件身份。

规范中的数值从真实变量及模式读取；变量变化后同时核对展示文字，避免说明值过期。维护记录说明新增、扩展、弃用、替代关系及影响范围。候选资产与正式资产分离，发布范围仅含已确认项及必要依赖。

Figma 与工程/导出文件分别指定维护源。导出记录变量身份、集合、模式、类型、值/别名及映射；不把 JSON 当作组件结构、文档布局和绑定的完整备份。回传先比较上次基线与当前源/目标，识别新增、修改、删除和双向冲突，只同步已确认差异；不无条件覆盖两边。工具不可读取或同步的关系明确标记。

#### 分层验收与测试调用

本分支验收统一从此处执行。按实际变化选择代表样本：目录更新选目录及长名称，表格更新选长文、增删和隐藏行，Token整理选实际涉及的变量、字体或组件；不固定要求每次都有颜色、字体和按钮。不涉及的检查注明不适用及原因，未执行的不能标通过。

| 排版与视觉 | 对照所采用模板及代表画面，检查长文增长、换行、溢出、列对齐、末行边线及允许覆盖；截图、名称或绑定率均不能单独证明一致 |
