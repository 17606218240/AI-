# 工作台使用说明

## 工作方式

文档是Codex的工作依据，工作台负责组织流程、查看与编辑文档、留存版本和记录节点确认。页面状态不替代文档中的范围、版本与授权。

## 页面入口

- 工作台：当前项目状态、三个流程入口、通用文档与实际工作区计数。
- 业务分析：需求接入 → 首期业务分析 → PRD与验证计划 → MVP可执行性评审 → 定版与开发交接。
- 开发启动：接收业务基线 → 识别项目与现状 → 制定约束与红线 → 核对开发条件 → 按批启动与回写。
- 设计与组件库：核对设计基线 → 按需归纳无 Token 设计稿 → 盘点组件与映射 → 生成外置验收库 → 调整与差异评审 → 定向回写与验证。
- 已有 Token 借鉴外部排版时，在「盘点组件与映射」启用参考排版适配分支，按语义复用、绑定并重排，验证设计与工程各自的实际结果。
- 设计还原、风格迁移或主题替换按设计流程正文盘点关键风格特征，分别映射到 Token、样式、组件、结构或资产；在既有映射和验收中记录处理结果，属性绑定与视觉对照分别验证。
- 持续维护的设计稿按需建立主组件、实例、Token 与代码属性的映射；按实际复用区分组件职责，记录候选、实现契约和已验证映射。
- 文档管理：按范围查看实际Markdown，支持编辑与历史版本。
- 任务记录：查看任务状态、产物和实际命令结果。

每个流程的输入、AI工作、产物和交接条件见本页下方展开项。流程定义保持原有内容，未重新启动业务分析。

## 文档编辑与历史

点击文档行唯一的查看入口，切换阅读、Markdown或修改版本。可编辑文档需填写修改说明后保存，系统留存修改前后快照。系统生成的执行记录只读。

同一文件被其他窗口修改时，旧编辑版本不能直接覆盖；请先重新读取并合并。保存期间避免重复提交和导航离开。未保存内容关闭或离开时提示，刷新/关闭浏览器使用原生离开保护。URL只保存定位，不保存未提交正文。

## 节点文档与确认

当前节点评阅作用域为通用流程配置，不代表项目业务PRD确认或开发授权。项目资料可独立登记查看，不以工作台活动项目状态推断对话中没有项目资料。

1. 选择节点，关联已有通用Markdown。
2. 查看并按需修改，保存修订。
3. 确认清单锁定打开时的修订号、SHA256和关联基线，由用户确认具体版本。
4. 确认后保存只读快照及Markdown评阅记录；当前及所有前置确认有效时，下一节点按钮才可推进。
5. 文件修订、关联变化或前置确认基线变化会使相应确认失效；原快照保留，需要重新评阅。

步骤条仍可浏览未来节点，不等于节点已经执行。页面每15秒及恢复焦点时核对确认状态，操作提交始终重新检查。确认历史和评阅记录可在节点面板查看，记录文件保存在documents/reviews/。

## 交给Codex执行

用Markdown任务单说明目标、授权范围、输入资料路径、采用版本、产物位置及验收要求；已有文档足够时直接引用，不复制整套正文。在当前对话中明确要求Codex读取并执行，再将结果写回文档。保存按钮不会自动唤醒Codex，无需另行登录CLI。

## 路由与返回

- 首页：#/overview。
- 流程节点：#/workflows/business/nodes/1；development、design同理，节点1至5。
- 文档列表：#/documents；scope参数记录范围。
- 文档：来源页面追加doc参数，tab参数记录阅读/编辑/版本；关闭保留来源节点，前进后退和刷新按地址恢复。
- 任务：#/tasks?task=任务ID。
- 非法页面或节点显示404，可返回工作台。

旧的#overview、#business等链接仍兼容。历史快照尚未单独编号到URL。

## 规范查看与维护

从[规范与架构权威入口](framework-architecture.md)进入通用红线、工作台技术实现约定和设计规范。规则不在说明书重复维护；界面参数不自动套给新项目。

## 文档与版本边界

通用流程说明尚未安装为Skill。修改Markdown不自动重写proposal.json结构化定义；需由Codex读取修改并同步。业务确认、开发采用和设计基线分开，文档保存不自动切换。财务BP、融资PPT和逻辑图按实际需要输出，不为凑文件而生成。

## 已有与待接入能力

已有：文档文件读写、修改说明、历史快照、冲突检查、节点关联与确认门槛、任务与原生命令结果查看。

尚未启用：新项目创建与项目级业务确认、项目采用版本流转、自动任务执行、Skill安装、逻辑图生成及数据图表。业务项目分析须有明确用户授权；项目级确认与自动执行尚未接入，不以文档存在冒充能力已启用。

## 旧实现处理

旧UI源码、旧样式和旧运行包已被新框架替换并删除；旧构建和校验脚本保留在archive/legacy-ui-tooling/，仅作历史参考，不参与当前构建。业务文档、历史版本、任务和评阅状态保留。历史智运试跑报告转为独立静态只读页面，保留原JSON及证据，不再依赖旧前端框架。
