# 工作流 Skill 能力总览

核对日期：2026-11-09。对象：已安装的 `project-flow-intake` 入口及其引用的共享工作流。本文是能力索引与使用说明，不替代各规则正文，不自动改变项目采用版本。

本表供查询，不是每个任务的必读输入。2026-11-09完成按需加载优化：入口收敛为路由，设计规范、项目特例和历史分离；读取与证据复用规则见通用启动流程。验证范围见[本次整理记录](walkthrough-report.md#2026-11-09工作流读取与执行优化)，不据字符减少推断Token或运行耗时。

## 1. 先看当前系统是什么

| 层级 | 当前形态 | 实际作用 | 不应误解为 |
| --- | --- | --- | --- |
| 已安装入口 Skill | `project-flow-intake`，调用 `$project-flow-intake` | 读取项目背景、识别交付端和改动类型，路由到对应规则 | 所有阶段都已封装成独立Skill |
| 通用启动路径 | 接入 → 判端 → 定范围 → 定方案 → 代表路径验证 → 交接迭代 | 跨项目重复使用的分析与接续方法 | 每个任务必须重走全部阶段 |
| 三条主流程 | 业务需求分析、开发约束与启动、设计与组件库，各保留五个主节点 | 规定输入、分析、产物、确认和进入条件 | 自动完成业务确认、自动开始编码 |
| 按需分支 | 并发开发、Token归纳、排版适配、Figma规范库、参考网站、动效等 | 只在相应需求出现时加载 | 所有项目都要启用、所有端都套同一技术栈 |
| 分流脚本 | `scripts/resolve-project-flow.cjs` | 读取项目配置，返回逐端建议、缺项、下一步及代表验证路径 | 自动验证资料真实性、自动生成项目或执行命令 |
| 工作台 | 文档、流程节点、评阅和任务等操作入口 | 展示和维护记录，承接已有服务能力 | 点击任意任务就能自动唤醒AI并完成工作 |
| 外部工具与专用Skill | Figma、浏览器、代码执行等按任务调用 | 实际读写设计稿、运行工程或检查页面 | 入口Skill自身内置所有外部能力 |

## 2. 状态怎样阅读

| 状态 | 本文含义 |
| --- | --- |
| 已接入 | 当前入口Skill明确调用该规则或分支 |
| 已定义 | 当前工作流正文有执行方法；由执行AI按需落实，不等于已有自动化程序 |
| 有工具支撑 | 已找到对应脚本、服务或可调用专用工具；是否适用仍需核对项目环境 |
| 有局部试跑记录 | 正文登记过具体试验与证据；只覆盖记录中的对象和版本，不代表当前全部通过 |
| 待实测 | 规则存在，但尚无本轮或相应完整路径的执行证据 |

以下状态来自当前文件核对与既有试跑记录，本次没有重新执行所有项目测试、Figma生成、发布或浏览器验收。

| 无界面服务分流 | API、数据处理、后台服务等 | 跳过品牌和UI，检查契约、权限、幂等、迁移与运行恢复 | 服务实现及验证路径 | 已定义；不强加组件库 |

## 4. 业务分析、PRD与最小MVP

| 能力 | 所在节点/触发条件 | 具体处理 | 主要产出 | 当前状态及边界 |
| --- | --- | --- | --- | --- |
| 需求与证据归纳 | 业务①需求接入 | 区分事实、用户决定、推断和未知；定位来源、日期和版本 | 需求摘要、来源与关键缺口 | 已定义；不把AI猜测包装成用户研究 |
| 用户与替代方案分析 | 业务②，定PRD前 | 检查真实任务、频率、痛点及手工/表格/不做等替代 | 业务分析中的问题与价值依据 | 已定义；个人自用验证不冒充市场样本 |
| 竞品功能与流程分析 | 业务②方向研究、业务③交互复核 | 按任务选产品，用同一输入、规则、结果和异常路径比较；记录实际取证范围 | 原业务分析/PRD中的可借鉴、不适用、待验证项 | 已定义；官方资料与登录实测分别记证据 |
| 商业与资源投入分析 | 涉及投入、收费、运营或预算 | 分析固定/变动/一次性成本、周期、公式及情景 | 原分析中的投入收益；必要时财务BP | 已定义；非商业项目不硬造营收预测 |
| 风险与可执行性分析 | 业务②、④ | 对照承诺与数据、接口、许可、环境和资源 | 风险结论、依赖与缺口、继续/缩小/先验证/暂停建议 | 已定义；当前阻塞与远期未知分开 |
| MVP范围划分 | 业务②至③ | 区分首期、先验证和后续保留，对齐优先级 | 本期范围与验收矩阵 | 已定义；竞品有的功能不会自动进入MVP |
| PRD业务模型 | 业务③ | 定义角色、对象、权限、输入输出、状态、异常和统计口径 | PRD对应功能章节 | 已定义；技术策略交开发流程决定 |
| 页面与功能归属 | 业务③ | 区分独立页面、页内操作、弹窗和系统交互，列功能归属与跳转 | 页面数量、功能列表、导航与返回路径 | 已定义；不是默认页面越多越完整 |
| 失败、未知与恢复 | 核心路径定义时 | 区分受理、成功、失败、超时和结果未知；定义草稿、返回及降级 | PRD规则与代表路径 | 已定义；未知不能填零或当成功 |
| 数据与图表口径 | 有计算、汇总、记录和图表 | 核对单位、时间、缺失、去重、修改删除后的统计影响 | PRD数据规则与验证项 | 已定义；具体模型按项目建立 |
| 验证计划 | PRD形成时 | 假设关联样本、证据、判定、周期和下一步决定 | 验证执行方案 | 已定义；单例不推断整体准确性或长期效果 |
| 一致性检查 | 定版、交接或规则变更时 | 对齐规则 → 页面/服务行为 → 验证证据 → 实施待办 | 原评审/交接中的差异与行动 | 已定义；借鉴一致性检查方法，不等于安装整套外部工具 |
| 变更与验证回流 | 定版后出现新发现 | 范围变更回②，规则变更回③，实现偏差在④判断并交⑤修复 | 原记录中的差异、采用决定、复测结果 | 已定义；不重建一套重复文档 |
| 逻辑图与交接 | 业务⑤ | 按复杂度生成必要图，核对当前PRD、状态及范围 | 逻辑图、当前文档索引、决定与待办 | 已定义；图源版本需可追溯，不自动采用新规则 |
