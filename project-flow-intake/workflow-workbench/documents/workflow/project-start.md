# 通用项目启动流程

适用新建、接手或新增端。工作台的栈与主题只管工作台。启动分析可以反复调用；采用与开工按用户指令及通用红线判定。

1. **接入**：登记目标、用户、关键任务、已有工程、约束、已采用依据与未知。接手项目先读现有实现，不重复初始化。
2. **判端**：对每个交付面分别判断用户、入口、设备、能力、分发与验收条件。B/C 是用户与任务维度，Web/App/小程序是运行维度，同一项目可同时有多端。先标候选，未知不能当确认。
3. **定范围**：对照现状和必要竞品证据，明确最小闭环、失败恢复、暂缓项及逐端验收。没有界面的项目跳过视觉与组件选型。
4. **定方案**：逐端比较运行形态、现有依赖、平台能力、团队、维护成本及发布条件；再决定品牌、组件和依赖边界。共有业务契约可复用，界面组件按运行环境隔离。
5. **代表路径验证**：选一条真实需求做最小样例，不为套模板先建五个组件。验证输入、失败恢复、目标设备和实际命令。方案/原型/真实业务分别记录。
6. **交接与迭代**：登记当前采用版本、入口、待办、风险和证据；模板升级只更新中心规则，不批量改旧项目。需要升级时比较差异并记录采用范围。

| 端型 | 先验证什么 | UI 方案的判断 |
|---|---|---|
| B 端 Web | 批量操作、权限、表格与录入密度、长任务 | 已有基座优先；复杂组件按真实需求比较 |
| C 端 Web | 首屏、触屏、发现与转化路径、必要时 SEO | 以品牌、可访问性与性能选择，不默认引后台库 |
| 移动 Web/PWA | 浏览器兼容、软键盘、安装或离线是否必要 | 验证 Web 能力上限，不能充当安装包交付 |
| 安装 App | 系统返回、权限、后台、真机、签名与分发 | 原生或跨平台候选按能力验证；不搬桌面 Web 组件 |
| 小程序 | 宿主规则、授权、包体、审核与 API | 用宿主兼容组件；只复用可映射的语义 Token |
| 无界面服务 | API/数据契约、权限、幂等、迁移与运行恢复 | 跳过组件与品牌 |

| 文件 | 谁维护，何时修改 |
|---|---|
| framework-architecture.md、common-redlines.md、project-start.md、brand-components.md | 平台统一维护，跨项目引用，不逐项目复制正文 |
| templates/project-profile.json、scripts/resolve-project-flow.cjs | 平台维护字段、分流与调用；项目不改模板原件 |
| 项目自己的 project-profile.json | 每个项目填一份；目标、当前依据、端、限制、实际检查命令按需调控 |
| 项目的技术决定、品牌值与映射、公共组件接口 | 项目维护；仅对采用的端有效，主题小改不触发重选栈 |
| 已验收证据和采用记录 | 追加或版本化，不覆盖旧结果 |

调用：`node scripts/resolve-project-flow.cjs --catalog` 查看可选端型；`node scripts/resolve-project-flow.cjs <项目配置文件>` 输出逐端检查重点、应读规范和未填字段。配置从 [模板](templates/project-profile.json) 派生。命令只读，不生成项目、不执行配置里的命令、不代表开工或技术采用。已有项目缺少配置时先沿已有记录核对，不强迁移。

每个交付端可填写三个字段。旧配置仍可解析，缺少的决策会在逐端结果里列出。

| 字段 | 填写方式 |
|---|---|
| `assets` | `status` 选 `adopted`（已采用资产）、`reference`（仅有参考）或 `none`（无资产）。在 `references` 中填可定位的源码、规范或参考链接 |
| `adoptionBasis` | 填本端已采用的决定与来源，尚未采用时明确写出。项目级 `baseline` 随结果提供作背景 |
| `change` | `kind` 选 `token`（局部视觉）、`feature`（业务功能）、`component`（组件缺口）、`replace-base`（替换基座）或 `redesign`（重新定设计方向）。`description` 写改动，组件缺口和基座替换在 `requiredBehaviors` 中列必须满足的行为 |

每端返回 `branchLabel`、`missingDecisions`、`nextAction` 与 `verification`。存在缺项时，下一步先补首个待决事项。顶层 `status` 继续表示基础输入完整性，分支输出是分析建议。无界面服务直接进入服务验证。依据和引用由填表者提供，解析器仅检查字段并按类型分流。

Codex 用户级入口为 `$project-flow-intake`。它调用同一解析脚本和规范，适用于新项目接入、已有项目接手与新增交付端。品牌研究通过已有的品牌与组件分支按需调用。
