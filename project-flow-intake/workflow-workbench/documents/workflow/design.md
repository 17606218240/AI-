# 设计与组件库 · 通用流程定义

范围：由已安装入口 `project-flow-intake` 按需读取的流程正文，未单独封装为Skill。修改不自动改变已有项目采用版本。

## 执行入口

跨阶段指令按[复合任务拆解与阶段交接](project-start.md#复合任务拆解与阶段交接)执行；本页维护设计专业标准。参数观察、候选、已采用和实际映射分别交接，排版或实现不能静默改变已确认业务含义。

先读对应节点的通用规则；涉及规范文档生成时，进入「规范文档生成约定（内部执行入口）」，通过专用分支核对模板登记后执行。[历史试跑与修改记录](design-history.md)仅用于追溯，不作为当前参数或已通过状态的来源。已有项目沿自己的采用记录，不自动切换到默认模板最新版。


各节点“确认”仅在缺少关键决定、冲突或范围变化时触发；已有授权和有效决定直接沿用。读取与复测遵循[按需读取与增量验证](project-start.md#按需读取与增量验证)，不以精简流程代替专业验收。

## 节点

### 1. 核对设计基线

用户输入：提供本期端/页面范围、规范/Token/组件库位置及已确认视觉；已有工程补充源码位置。

分析：区分有效规范、参考、草稿与占位模板，核对来源、Token有效值与适用端；当前/历史状态按组件和版本登记，不用整库“已接入/未接入”代替；明确CSS/JSON/规范/展示页各字段的维护源、生成目标和检查方式；旧说明结合后续决定判读，不按文件时间或截图猜权威。

产物：基线登记：来源/版本、组件采用状态、维护与生成职责、冲突和缺口。

确认：只对有效来源选择、冲突或新视觉方向补决定；已确认基线可沿用。

进入条件：当前范围及有效基线明确，各载体职责可追踪；已有资产复用，缺规范可先探索，占位Token不用于工程。

### 按需分支：无 Token 设计稿归纳

提取与采用分开：先确定本批为保真保留原值，还是按目标项目间距尺度规范化。项目维护基础间距尺度、语义用途、适用端及例外；通用流程不强制8px或其他固定网格。规范化按空间用途选择档位，不能机械取最近值；保留原值证据，调整后检查重排、内容增长及适用窄屏。间距网格不自动约束字号、行高、描边、圆角或媒体比例。

基线核对后，只有本期设计稿缺少可用语义 Token 时才进入。已有设计系统时优先复用，仅归纳缺失角色。一次性交付只整理本期工程所需角色。持续维护的设计稿再执行设计侧绑定。

1. 盘点代表页面、组件和状态，记录来源版本、图层标识、属性、原始值和现有绑定。区分直接读取的事实与 AI 推断。
2. AI 先按用途、作用域和应一起变化的位置归类，再比较数值。页面内距与卡片内距同为 24px 时，可共享基础值。需要独立调整时保留两个语义角色。
3. 优先沿用项目词表。缺省命名采用 `类别/用途/角色[/状态]`，例如 `color/text/secondary`。写入前核对当前变量与项目词表，统一大小写和分隔符，并按用途、作用域、类型及主题含义判断同义项。复用已有变量 ID。同名异义或用途不明时，附图层及状态集中复核。只有稳定的新角色才新增。
4. 在现有组件/Token 映射表补记原始值、语义、复用或新增决定、变量 ID 与绑定结果。对持续维护的稿件，在明确的目标文件中批量绑定无歧义项。无法读取或绑定的属性标为待验证。
5. 在同一批页面和同一基线上运行两次。第一次记录新增、复用、绑定及待复核项。第二次重新读取实际变量和绑定，验收新增变量为零、既有 ID 和绑定保持一致。抽查单变量改值仅影响预期图层，并恢复试验值。仅重算映射时，结果记为映射复测，Figma 写入验收仍待执行。

分支输出沿用现有映射表，接入下一节点核对工程消费路径。

参考提取按本期交付范围检查覆盖。每项值或规则标为已观察、归纳候选或补充设计，并关联来源与状态。仅对明确需求所必需、且已有有效项目规范定义的缺失状态、主题或端进行补齐并验证；缺少来源的新效果或交互保持候选，不因“补齐”而自动实施，自由设计须遵守通用红线R01的明确授权边界；远期范围记录缺口。采用状态独立登记，观察事实和候选不能直接推导项目已采用。

### 2. 盘点组件与映射

首次建立本批映射基线，后续从受影响的Token、样式、组件和消费者补差；范围不明、跨主题/跨端或共享契约变化时扩大检查。增量盘点不替代本次视觉、状态及最终组合验证。不为无变化项目重复全库扫描或导出。

用户输入：说明代表场景、重点状态和当前任务；无工程时提供首批页面需求。

分析：盘点真实组件、主题/样式、属性和依赖，标注实际运行组件、源码快照、HTML近似或待实现；快照不是独立安装包；映射记录源/目标标识和指纹、场景/状态及默认/局部覆盖；Token逐项对应工程主题、CSS或组件属性的消费路径与转换。

产物：组件/Token映射及首批覆盖：运行类型、场景、覆盖优先级和工程消费路径。

确认：确认首批覆盖及缺失组件；不为了“完整库”预建无需求组件。

进入条件：本批可同步项定位到真实目标与使用场景；近似/快照不能据此认定视觉或运行行为等价。

### 按需检查：风格特征与承载映射

涉及设计还原、风格迁移或主题替换时，在本节点执行；普通业务调整不额外启动整套风格盘点。先从本批代表样本确定必须保留的风格特征，再开始映射。按实际内容检查填充、描边、渐变、内外阴影、圆角、透明度、字体及间距，记录来源图层/组件、版本和适用状态；不能把未展示的状态或截图推断写成已读取事实。

按用途选择承载方式：可独立调节的数值或颜色用 Token；多层高光、投影等组合可由效果样式或组件承载；依赖图层、遮罩、纹理的效果保留对应结构或资产。不要求全部效果 Token 化，也不要求所有卡片具有同一种表面效果。具体参数和表面角色在项目设计系统维护，通用流程不预设视觉风格或组件基座。

沿用现有映射记录，为每项关键特征登记目标 Token/样式/组件/结构或资产、消费位置及处理结果：已应用、不适用（说明原因）、待确认或待实现。用途不明时提出候选，不自行补造或把缺失效果视为不适用。需要独立变化的角色即使当前同值也分别判断语义；既有词表与查重规则继续适用。

### 按需分支：设计组件与代码契约

在持续维护的设计稿需要跨页面复用、或交接代码实现时启用。一次性页面可只映射本批 Token 和少量公共组件。基础元素、功能组合和业务组合按职责与实际复用区分，只有稳定复用或独立状态契约需要时才抽取组件；项目决定名称与目录。

- 需要规范文档时按[呈现契约](design-spec-documentation.md#设计规范呈现契约2026-11-08)记录参数；角色、别名、来源、采用状态及代码契约在映射/维护记录中维护，用户明确需要语义化文档时再展示。Figma 中适用属性绑定 Variables，组合文字等属性使用样式，记录工具不支持的绑定。
- 沿用现有组件/Token 映射表，记录文件/主组件 ID 或 key、版本、变体与属性、嵌套组件身份、Token/样式引用及实例覆盖。页面优先使用主组件实例，核对脱离实例或局部覆盖对映射的影响。
- 对应真实工程组件时，登记公共导入入口、导出名、属性与变体转换、数据/事件及必要状态契约。设计 Token 到工程视觉消费路径与主组件到代码 API 分别记录。代码尚未实现时标为实现契约，组件同名不作为映射验证依据。
- 实现交接须验证所用工具能读取组件身份、属性、绑定及映射记录。按工具实际能力使用 Code Connect 或项目映射记录；工具不可读的关系保留可交接记录并说明限制。
- 验收选取两个共享元素的代表页面，按实际交付范围覆盖文字、操作、输入及重复组合。核对单 Token 改值影响、重复执行无同义变量/组件新增、主组件 ID 和实例绑定稳定，再恢复试验值。进入代码实现时，另核对代表页面是否消费指定组件与属性、是否仍有需要猜测的语义，以及视觉和适用交互结果。

规则维护、设计绑定、代码映射及代表页面实现分别登记状态。Figma 访问失败时记录实际失败点与待验证项，不能以映射草案作为绑定或代码验收结果。

### 按需分支：参考排版适配自有 Token

在「盘点组件与映射」中，当项目已有有效 Token，并希望借鉴外部排版时启用。项目 Token 为本批视觉基线，参考用于识别布局关系和信息层级。此分支与「无 Token 设计稿归纳」按输入选择；已有规范仅缺个别角色时，就地补缺。

1. 明确参考的页面、区块、来源版本和本批目标，记录希望借鉴的分栏、顺序、对齐、比例、留白及响应式关系。区分可读取值与截图推断，记录需要调整的结构或交互影响。
2. AI 按内容用途、层级、作用域和状态，把参考元素映射到项目已有语义角色，再取该角色在目标主题、端和尺寸档位下的有效值。标题、正文、页面内距、卡片内距及卡片间距分别判断。禁止仅按数值接近选择 Token，或仅因参考数值不同创建新变量。
3. 沿用项目词表及「无 Token 设计稿归纳」的命名、同义查重和复用 ID 规则。在现有映射表记录来源图层/元素、原值及证据、目标语义及变量 ID/工程路径、目标值、复用或缺口决定和绑定状态。缺失角色先检查现有公开覆盖接口，稳定复用需求才提出新增角色；歧义集中复核。
4. 设计侧优先绑定项目已有 Variables 和文字样式，记录集合、模式和实际绑定。受工具或属性支持限制的项使用适用样式或工程映射，并注明未绑定范围。工程侧沿既有主题、CSS 变量或组件公开属性消费同一语义。设计绑定与工程同步分别登记。
5. 应用目标字号、行高、间距及尺寸后，重新检查列宽、换行、容器高度、对齐、留白和内容密度，按项目响应式规则重排。保留已选排版关系的同时解决目标规范造成的溢出或层级问题，记录必要差异。新增例外沿现有差异评审处理。
6. 用本批代表页面核对桌面和窄屏的实际值、文字可读性、溢出、对齐及适用交互。单独改一个目标 Token，检查对应位置跟随、其他角色保持原值后恢复试验值。重复执行前重新读取实际变量和绑定，核对无同义新增、既有 ID 与绑定稳定。结果分别标明映射、设计绑定、工程消费及视觉验证的通过范围。

参考适配同时执行「风格特征与承载映射」：明确参考方提供的排版/内容关系与目标系统提供的视觉特征，例外说明来源和原因。目标样本的高光、投影、渐变等不能因纯色已绑定而漏掉；逐项登记处理结果，并核对实际应用。

输出复用现有组件/Token 映射与差异评审，进入「生成外置验收库」及「定向回写与验证」。规范已补充与实际项目试跑分别记录。

### 样式作用域判断

先列出应该一起变化的位置，再选择能覆盖这些位置的最小作用域。全局范围复用共享语义 Token；同类组件共享且需要独立调节时，使用组件级语义 Token。仅在一个区域或实例生效的差异，优先用所选基座的公开覆盖接口。仅当差异具有稳定、可复用的语义时才新增角色。按项目需要采用这些层级，具体映射由项目决定。

初始值相同的角色可以独立维护。验收时逐项只改一个角色，同时检查目标位置和应保持原值的位置，并登记消费位置、实际测量值及结论。

### 可选分支：参考网站风格提取与扩展

当目标为网站链接复刻、提取风格 Token 并补充缺失组件时，进入[参考网站风格提取与扩展](website-style-extraction.md)。依次完成代表样本、可编辑校准、风格规则、缺失区块适配和整页验证，记录来源事实及新增设计决定。

### 可选分支：参考交互与动效

只加载本次观察到的交互机制和必要上下文，不默认比较或引入所有动效库；实际触发、反向、中断、窄屏和降级等适用验收仍须覆盖。

当项目明确需要复现参考交互，或核心体验依赖滚动、拖拽、状态过渡时，在「盘点组件与映射」启用。先观察实际页面，区分可复现的行为、公开资料说明和实现推断。Framer 的公开行为可参考其[动效概览](https://www.framer.com/academy/lessons/framer-animations-overview)和[滚动动效教程](https://www.framer.com/academy/lessons/scroll-animations)。

| 观察到的行为 | 实现判断 |
| --- | --- |
| 进入视口后按固定节奏播放 | 视口触发，定义进入阈值、时长及重播条件 |
| 滚动到任意位置都能停在对应画面 | 连续进度映射，定义滚动容器、起止范围及关键值 |
| 跨过区块边界时切换外观 | 区块触发状态切换，定义当前区块与边界判定 |
| 点击、悬停或拖拽改变组件外观 | 组件状态与过渡，定义输入方式、目标状态和打断行为 |

在现有组件映射或设计评审中就地记录参考链接、作用区域、触发与状态、起始/中段/结束画面、反向与打断行为、窄屏与触屏、减少动态效果策略及实现依据。项目根据需求选择原生能力、平台接口或动效库。多个机制涉及同一滚动容器时，明确谁控制滚动位置，谁只读取进度。

在「生成外置验收库」先隔离验证一条代表交互。「定向回写与验证」记录实际工程中的桌面、窄屏、触屏及减少动态效果结果，注明未测项。至少核对触发边界、快速反向或中途打断、离开区块后正常滚动，以及降级后内容可读、主要操作可用。

首个复测样板为 [Save.design](https://save.design/) 的卡片收拢区块。先采集散开、收拢途中、汇聚到文件夹三个画面，缓慢滚动并在中段停住，随后快速反向，核实连续进度和阈值播放的区别。若确认连续进度，优先用原生滚动和局部 sticky 舞台试做，把区块进度映射到卡片位移、旋转与缩放。核对回滚是否连续、区块前后是否可正常滚动，窄屏或减少动态效果模式下仍可读取内容。此处登记的是复测方案，工程实现与本轮实测待执行。

### 3. 生成外置验收库

用户输入：选择本批展示与验收场景；有既定展示壳时提供位置。

分析：复用已有验收库与统一展示壳，按维护源生成或补差；优先隔离渲染实际组件，近似示例注明差异，不重复建同义库；按本批场景/状态展示，保留默认与上下文差异；演示数据隔离，权限/接口/业务状态机不从示例移植。

产物：外置入口/资源、带运行类型的场景展示及覆盖/未覆盖清单；引用基线与映射。

确认：对照代表场景确认呈现与覆盖；查看页生成不等于工程同步完成。

进入条件：入口/资源可打开，文字与状态可读，交互反馈真实；是否离线按交付目标核对。

涉及风格转换时，在既有展示入口中提供目标风格样本与转换结果的可对照视图，标明基线、主题、状态及必要的尺寸差异；不另建同义验收文档。无法访问的样本或状态注明未验证。

### 4. 调整与差异评审

用户输入：可在独立对话指出组件/Token/场景及期望变化。

分析：先核对工程/设计基线；按Token消费路径定位受影响主题、样式和组件，不做跨格式全局替换或全库尺寸统一；登记确认差异、场景/状态、必要依赖及检查计划；按维护/生成职责同步载体，结构/属性/行为变化另列影响。

产物：本批确认差异及目标清单；引用映射、覆盖范围和未同步项。

确认：确认本批视觉及回写范围；结构/属性/行为变化另核对技术/业务影响，已有明确授权可沿用。

进入条件：已确认变更可定位且无未处理关键冲突；只改外置库时明确工程仍未同步。

### 5. 定向回写与验证

风格转换验收分别核对属性应用与实际画面。属性检查发现缺失的填充、描边、效果或承载结构；视觉对照检查层级、对比、高光与空间感是否符合本批目标。每项关键特征须有处理结果；尚待确认或实现的项标部分完成，不能宣称该范围风格转换全部通过。绑定率、哈希或属性存在均不能单独证明视觉完成。独立 AI 复核如被采用，应读取目标样本和实际结果，不能只转述执行者结论；看不到实际结果时仅登记属性检查范围。

用户输入：明确工程同步目标与本批范围；仅预览时停在外置库。

分析：回写前核对源/目标指纹和用户成果；仅同步确认差异与必要依赖，保留业务行为及冻结端，变更基线先重算；分别记录源码/映射一致性、浏览器视觉、键盘/交互与必要业务回归；历史证据标版本和场景，检查相称，不将哈希一致或局部通过当全量验收。

产物：实际文件/映射更新、版本对应及分层证据；部分完成、未覆盖与未同步项。

确认：范围或关键实现不兼容时定向确认；不能自动迁移技术栈或越过冻结边界。

进入条件：确认差异完成且证据覆盖明确；外置调整、工程同步与验证分别记状态，失败保留待处理，不以局部一致宣称全部完成。

## 产物规则

- 设计基线与映射：有效组件/版本状态、载体维护/生成职责、源/目标及指纹；映射含运行类型、场景覆盖和Token消费路径。 
- 外置HTML验收库：复用统一入口及必要资源，按场景展示实际组件或标明近似；引用基线/映射，示例数据隔离。 
- 设计修订与同步清单：引用本批映射，登记确认差异、受影响目标/场景、必要依赖和保持项；不重抄规范或全局替换。 
- 工程同步与验证记录：实际文件与设计/工程版本对应；源码/映射、视觉、交互及必要业务检查分别记证据，明确部分完成、未覆盖与未同步。

## 响应式与尺寸选档

在「盘点组件与映射」明确三层职责。设计 Token 定义断点或容器阈值、文字角色、控件尺寸和间距的数值；项目响应式规则按可用宽度、操作用途和输入方式决定何时选档；所选组件基座或平台适配层把档位映射到公开接口及布局。优先用换行、重排或容器响应解决窄屏，正文和关键操作需保持可读、可触达。

业务组件按真实复用场景提供变体。默认一档即可，只有密度、结构或操作场景确实不同才增加档位；尺寸变化优先复用组件结构与状态契约。在「定向回写与验证」用同一条代表路径核对桌面和窄屏的实际字号、控件高度、换行或溢出与操作结果。触屏适配列出目标设备与实际验证状态。具体阈值、尺寸与组件库映射由项目记录。
